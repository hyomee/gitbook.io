# 프롬프트

## 1. 기본 용어

* **프롬프트-컴프리션(Prompt-Completion):** 질의-답변
  * 프롬프트: 텍스트, 멀티모달 모델의 경우 이미지, 비디오 ...&#x20;
* **토큰(token)**: 단어 조각(단어, 음절) - LLM(대형 언어 모델)이 텍스트를 처리하기 위한 기본 단위
  * 단어당 영문: 1.3, 한글:2, 공백도 토근계산이 됨&#x20;
  * 모델 관점에서 문서는 토근의 순서일 분



## 2. 프롬프트 엔지니어링

인공지능 모델, 특히 대형 언어 모델(LLM)에게 원하는 결과를 얻기 위해 입력 텍스트(프롬프트)를 효과적으로 설계하고 최적화하는 기술이다.

### 2-1. 프롬프트 구조

LLM(대규모 언어 모델)에 효과적으로 명령을 내리고, 원하는 출력을 얻기 위해 입력 텍스트(프롬프트)를 체계적으로 설계하는 형식으로 프롬프트의 구조는 내용의 전달, 정보 맥락 제공, 출력 기준 명시 등으로 구성된다.&#x20;

#### 2-1-1. 핵심 요소

* **지시사항(Instruction)**: 모델에 특정 작업(예: 요약, 번역, 설명 등)을 명확히 요구하는 부분.

* **맥락(Context)**: 요청이 이루어지는 배경 정보나 필요에 따라 추가적인 설명, 예시, 상황 등을 포함.

* **역할/페르소나(Role/Persona)** - AI에게 특정 전문가나 역할을 부여하여 답변의 스타일과 품질을 조정한다. "당신은 10년 경력의 마케팅 전문가입니다"처럼 역할을 명시합니다
* **입력 데이터(Input data)**: 모델이 처리하게 될 실제 정보, 질문, 데이터 등을 제공. 분석할 문서, 번역할 텍스트, 검토할 코드 등이 해당합니다
* **출력 명세(Output specification)**: 원하는 출력의 형식이나 조건(예: 표, 글머리표, 분량 등)을 지정
* **예시:**&#x20;

```
지시사항 : 2023년 1분기 판매 데이터를 분석해서 주요 제품 판매 추세와 향후 전망을 포함한 보고서 작성.
맥락 : 표와 그래프를 활용하여 데이터를 시각화할 것.
입력 데이터 : (판매 데이터 테이블이 삽입됨)
출력 명세 : 표, 그래프, 서술 요약까지 포함
```

* **대화형 모델에서 역할(Role):**&#x20;
  * 다양한 주체(사람—AI—시스템 등)가 번갈아 대화에서 메시지를 교환할 수 있도록 논리적 시퀀스를 명확히 구분하기 위해 도입.
  * 역할 정보가 포함되면, 모델이 발화자의 관점, 대답 방식, 맥락 유지 등에 더욱 적절히 대응할 수 있다.
* **대화형 모델에서 역할(Role) 예시:**&#x20;
  * "system" 역할: 대화의 컨텍스트나 인공지능의 성격, 목표를 설정, 안내합니다.
  * "user" 역할: 실제 질문, 요청, 명령 등 입력을 담당합니다.
  * "assistant" 역할: AI(모델)가 사용자의 요청에 대한 답변을 생성합니다

```
[
  { "role": "system", "content": "너는 친절한 어시스턴트야." },
  { "role": "user",    "content": "오늘 날씨 어때?" },
  { "role": "assistant", "content": "오늘은 맑은 날씨가 예상됩니다." }
]
```

#### 2-1-2. 콘텍스트(Context)

대화의 흐름(이전 질문/응답, 상황, 목적 등)을 이해하기 위해 필요한 배경 정보로 모델이 질의를 잘 이해하고 적절하게 응답하도록 사용자가 모델에 전달하는 관련 정보나 세부 사항을 말한다. 즉 즉, **콘텍스트란 어떤 일의 의미를 명확하게 이해하기 위해 알아야 하는 '주변, 환경, 맥락, 배경' 정보**를 뜻으로 동일한 문장이나 행동이라도 콘텍스트에 따라 해석이나 의미가 달라질 수 있다.

AI 모델(특히 GPT 계열 등)에 입력되는 **프롬프트(질문·지시문 등)를 설계할 때, 원하는 응답을 유도하고 맥락을 잘 반영하도록 컨텍스트(배경·상황·이전 내용 등)를 효과적으로 포함하는 방법을 다음과 같은 것이 있다.**

* **1.프롬프트 내 명시적 콘텍스트 삽입**
  * 프롬프트에 **이전 대화 내용, 사용자 정보, 배경 설명 등**을 명시적으로 포함
    * 예시:
      * “지금까지 우리 대화는 다음과 같습니다: A: ... B: ... 이번엔 ...을 설명해줘.”
        * “사용자는 Python 초보자입니다. 파이썬 리스트에 대해 쉽게 설명하세요.”
* **2.롤(work role) 및 목적 지정**
  * 모델에게 **역할 임무/지침을 부여**하여 일관된 맥락 유지
    * 예시:
      * “너는 여행 전문 상담사야. 친절하고 자세하게 유럽여행 코스를 추천해.”
        * “기술 문서를 작성하는 전문가 입장에서 코드를 리뷰해줘.”
* **3.대화 이력(History) 누적 전달**
  * 여러 턴(turn)의 이전 Q\&A 내용을 프롬프트 앞부분에 정리해 모델에 제공
  * 최근 n턴 또는 핵심만 요약해 포함
    * 예시:&#x20;
      * “Q1. ... A1. ... Q2. ... A2. ... Q3. ... <사용자 입력>”
* **4.슬롯(Slot) 기반 정보 구조화**
  * 대화의 **상태 정보(슬롯)에 각종 변수(날짜, 장소, 요구사항 등)을 저장**하고 프롬프트에 반영
    * 예시:
      * “현재까지 입력된 정보: 날짜=10/25, 장소=서울, 유형=한식. 이 조건에 맞춰 추천 메뉴를 알려줘.”
* **5.고급 “시나리오 기반 프롬프트”**
  * **특정 상황, 예시, 가이드라인, 금지사항** 등을 세부적으로 포함
    * 예시:
      * “아래 조건을 모두 반영해 대답해야 해: 1) 답변은 3문장 이내로, 2) 쉬운 용어 사용, 3) 예시 포함, 4) 농담 금지.”

***

* **6.Placeholders & Dynamic Context**
  * 자동화 시스템에서는 **동적으로 프롬프트 안에 최신 컨텍스트**(유저명, 최근 검색 정보 등)를 채워 넣음
    * 예시:
      * “{user\_name}님, 지난번 문의하신 {last\_issue}에 대해 추가 설명드립니다.”

***

* **7.Few-shot/Zero-shot Learning 기법**
  * **유사 예시(few-shot) , 불필요 정보 배제(zero-shot), 하나만(one-shot)**
    * 예시:
      * “예시1: ... 예시2: ... 이제, ‘...’에 대해 같은 형식으로 답변해줘.”

### 2-2. 프롬프트 엔지니어링 작성 방법

* **명확하고 구체적으로 작성:** 모호한 표현을 피하고 목적, 조건, 형식을 최대한 상세히 명시합니다. "좋은 마케팅 전략을 알려줘" 대신 "B2B SaaS 스타트업을 위한 저예산 디지털 마케팅 전략 5가지를 구체적인 실행 단계와 함께 제안해주세요"처럼 작성한다.​
* **창의력을 발휘하게 작성**: LLM을 자극하여 좋은 답변을 유도해야 한다.
* **텍스트양이 많으면 인스트럭션을 프롬프트 끝으로 이동**&#x20;
* **주제를 명확하게**: 누가, 언제, 어디서, 어떻게, 왜 중 하나를 명확하게 서술
* **명시적 지시문을 사용**
* **부정적인 표현은 하지 않는다.**
* **구체적인 응답 형식을 제시 한다.**
* **모델이 자신 있게 대합할 수 없다면 어떻게 해야 하는지 정의:** 환각을 없애는 방법&#x20;
* **모델에게 단계별 사고를 하게 요청**: 처리 순서 명시&#x20;
* **응답을 평가하게 유도**: 최종 답변을 원하는 답변을 받기 위해 답변에 대한 평가를 할 수 있도록&#x20;
* **구조화와 구분:** 지시문과 데이터를 명확히 구분합니다. 구분자(###, """, XML 태그 등)를 사용하여 프롬프트의 각 부분을 구조화하면 AI가 더 정확히 이해한다.​

```
text###Instruction###
다음 텍스트를 요약해주세요.

###Context###
이 텍스트는 5-7세 어린이용 교육 자료입니다.

###Input Data###
[분석할 텍스트]

###Format###
3개의 짧은 문장으로 요약
```

* **행동 중심 동사 사용:** "생성해주세요", "요약해주세요", "분석해주세요"처럼 명확한 행동 동사로 시작한다. "\~할 수 있나요?"처럼 약한 표현보다 직접적인 명령이 효과적이다.​

### 2-3. 주요 프롬프팅 기법

| 기법                    | 설명                 | 예시                                       |
| --------------------- | ------------------ | ---------------------------------------- |
| 제로샷(Zero-shot)        | 예시 없이 요청만 단순 전달    | “기후 변화 시대의 인공지능 역할을 요약해 주세요”​            |
| 원샷(One-shot)          | 한 가지 예시와 함께 요청     | “다음 예시와 같은 형식으로 요약해 주세요: …”​             |
| 퓨샷(Few-shot)          | 여러 예시를 추가 제공       | “아래 두 예시처럼, 새로운 글을 동일한 방식으로 요약하세요”​      |
| CoT(Chain-of-Thought) | 단계별 추론 유도          | “문제 해결 과정을 단계별로 설명하고, 마지막에 결론을 적어주세요”​   |
| 롤플레잉                  | AI에게 특정 역할 부여      | “당신은 스타트업 투자 전문가입니다. 해당 사업계획서를 검토해 주세요”​ |
| 출력을 명시적으로 제한          | 형식, 톤, 분량 등 명확히 지정 | “항목별 표로 결과를 반환해 주세요. 500자 미만으로 요약해 주세요”​ |

* **제로샷(Zero-shot) 프롬프팅:** 예시 없이 직접 작업을 요청하는 방식으로. 일반적인 작업이나 빠른 답변이 필요할 때 사용한다.
  * 예시: "다음 문장의 감정을 분석해주세요: '이 영화는 정말 환상적이었어요!'"
* **원샷(One-shot) 프롬프팅:** 한 가지 예시와 함께 작업을 요청하는 것으로  AI가 원하는 형식과 스타일을 이해할 수 있도록 한다.
  * 예시:

```
text다음 예시처럼 제품 설명을 작성해주세요.

예시:
제품: 무선 마우스
설명: 인체공학적 디자인으로 장시간 사용에도 편안한 블루투스 마우스

이제 다음 제품의 설명을 작성해주세요:
제품: 스테인리스 물병
```

* **퓨샷(Few-shot) 프롬프팅**여러 예시(보통 2-5개)를 제공하여 AI가 패턴을 학습하도록 하여 복잡한 작업이나 특정 형식이 필요할 때 효과적이다.
  * 예시:

```
text감정 분석 예시:

텍스트: "제품이 형편없어요." → 감정: 부정적
텍스트: "정말 유용하고 가치 있어요." → 감정: 긍정적
텍스트: "괜찮았어요." → 감정: 중립적

이제 다음 텍스트의 감정을 분석해주세요:
텍스트: "작동이 안 돼요!"
```

* **체인 오브 쏘트(Chain-of-Thought, CoT) 프롬프팅:** 복잡한 문제를 단계별로 분해하여 추론하도록 유도하는 기법으로 수학 문제, 논리적 추론, 복잡한 분석에 특히 유용하며 CoT 프롬프팅은 모델이 중간 추론 과정을 명시적으로 생성하게 하여 더 정확하고 설명 가능한 답변을 얻을 수 있게 한다.
  * 예시:

```
text다음 문제를 단계별로 풀어주세요:

1. 먼저 핵심 정보를 파악하세요.
2. 필요한 계산 과정을 설명하세요.
3. 각 단계의 결과를 보여주세요.
4. 최종 답을 제시하세요.

문제: [복잡한 수학 문제]
```

* **역할 부여(Role Prompting):** AI에게 특정 전문가나 페르소나를 할당하여 답변의 관점과 품질을 향상시킵니다.​
  * 예시: "당신은 20년 경력의 데이터 과학자입니다. 머신러닝 초보자에게 신경망의 작동 원리를 설명해주세요."

### 2-4. 반복적 개선 프로세스(PIER)

완벽한 프롬프트는 한 번에 만들어지지 않으므로  지속적인 테스트와 개선이 필요하다.​

1. **P (Prompt)** - 초기 프롬프트 작성: 기본 요구사항을 담아 첫 프롬프트를 작성.
2. **I (Inspect)** - 결과 검토: AI의 응답을 분석하고 부족한 부분을 식별.
3. **E (Enhance)** - 프롬프트 강화: 발견된 문제를 해결하기 위해 프롬프트를 개선.&#x20;
   1. 더 구체적인 지시, 추가 맥락, 명확한 형식 요구 등을 보완한다.
4. **R (Repeat)** - 반복: 원하는 결과를 얻을 때까지 위 과정을 반복합니다.
5. 반복 개선 예시:​
   1. 초기: "동화 작성해줘"\
      → 1차 개선: "환경 보호를 주제로 한 어린이 동화를 작성해줘. 주인공은 바다거북이야."\
      → 2차 개선: 페르소나, 맥락, 구체적 작업, 형식을 모두 포함한 상세 프롬프트\
      → 3차 개선: 대상 연령, 사용 목적, 구체적 캐릭터 이름과 성격, 포함할 메시지, 세부 구조까지 명시

### 2-5. 실전 작성 팁

* **구분자 활용**: ###, """, XML 태그 등을 사용해 지시문과 데이터를 명확히 구분합니다.​
* **제약 조건 명시**: 분량(500자 이내), 어조(전문적인/친근한), 회피할 내용 등을 명확히 지정합니다.​
* **예시의 다양성**: Few-shot 프롬프팅 사용 시 긍정적 예시와 부정적 예시를 모두 포함하고, 다양한 케이스를 보여줍니다.​
* **단계별 지시**: 복잡한 작업은 여러 단계로 나누어 순차적으로 진행하도록 합니다.​
* **출력 검증 요청**: "답변의 정확성을 검토하고 확신이 없다면 언급해주세요"처럼 자체 검증을 요청할 수 있습니다.​
* **템플릿 활용**: 반복적인 작업에는 재사용 가능한 템플릿을 만들어 변수만 교체하여 사용합니다.​

## 3. 추론 구성 매개변수

대규모 언어 모델(LLM)의 추론(inference) 단계에서 사용되는 매개변수는 모델이 텍스트를 생성하는 방식을 제어하며, 출력의 창의성, 일관성, 다양성, 길이 등을 조정할 수 있다. 이러한 매개변수는 모델의 학습된 가중치를 변경하지 않고, 다음 토큰을 선택하는 확률 분포를 조정한다.

### 3-1. 핵심 샘플링 매개변수

* **Temperature (온도):** 모델 출력의 무작위성과 창의성을 제어하는 가장 중요한 매개변수로  모델이 다음 토큰을 예측할 때 생성하는 확률 분포를 조정한다.
  * **낮은 값 (0.0-0.3)**: 확률이 높은 토큰이 선택될 가능성이 증가하여 더 결정론적이고 일관된 출력을 생성한다. 요약, 기술 문서 작성, 코드 생성, 사실 기반 질의응답에 한다.​
  * **중간 값 (0.5-0.7)**: 일관성과 다양성의 균형을 맞춘다. 챗봇 응답에 적합하다.​
  * **높은 값 (0.8-1.2)**: 확률 분포를 평탄화하여 낮은 확률의 토큰도 선택될 가능성이 높아지며, 창의적이고 다양한 출력을 생성한다. 창작 글쓰기, 브레인스토밍, 아이디어 탐색에 유용하다.​
  * **극단값 (2.0 이상)**: 확률 분포가 지나치게 평탄화되어 비일관적이고 무의미한 출력이 생성될 수 있다.
  *   **예시**: "I hear the hoof beats of" 다음에 올 단어가 horses(0.7), zebras(0.2), unicorns(0.1)의 확률을 가진다면, temperature가 높으면 "unicorns"가 선택될 확률이 증가하고 "horses"가 선택될 확률은 감소한다.​


*   **Top-P (Nucleus Sampling, 핵 샘플링):** Top-P는 확률의 누적 합이 특정 임계값에 도달할 때까지 확률이 높은 토큰만 고려하는 샘플링 방식으로 Temperature가 확률 분포 자체를 조정한다면, Top-P는 선택할 토큰의 범위를 제한한다.

    * **낮은 값 (0.1-0.5)**: 가장 높은 확률의 소수 토큰만 고려하여 더 집중되고 예측 가능한 출력을 생성한다. 코드 생성, 기술 문서에 적합하다.​
    * **높은 값 (0.7-0.9)**: 더 많은 토큰을 고려하여 다양성과 창의성이 증가한다. 창작 글쓰기, 탐색적 응답에 유용하다.
    * **예시**:  토큰 A(35%), B(25%), C(10%)가 있고 Top-P가 0.5이면 누적 확률 50%까지인 A만 선택. Top-P가 0.6이면 A와 B(누적 60%)가 모두 고려된다.


* **Top-K:** Top-K는 확률이 가장 높은 상위 K개의 토큰만 고려하도록 제한. Top-P와 달리 고정된 개수의 토큰을 선택한다.
  * **낮은 값 (10-30)**: 선택 범위를 줄여 더 집중된 출력을 생성​.
  * **높은 값 (50-100)**: 더 많은 토큰을 고려하여 다양성이 증가.​
  * **0**: 모든 토큰을 고려합니다.​
  * **예시**: Top-K=2로 설정하면 ""I hear the hoof beats of" 다음에 올 단어가 horses(0.7), zebras(0.2), unicorns(0.1)의 확률을 가진다면  horses(0.7)와 zebras(0.2)만 고려되고 unicorns(0.1)는 제외된다.

<mark style="color:orange;">**Temperature 또는 Top-P 중 하나만 조정할 것을 권장한다. 두 매개변수를 동시에 사용할 수도 있지만, 효과가 중첩되어 예상하지 못한 결과를 낳을 수 있다.**</mark>

### 3-2. 출력 제어 매개변수

* **Max Tokens (최대 토큰):** 모델이 생성할 수 있는 최대 토큰 수를 제한. &#x20;
  * 더 긴 값: 더 풍부한 컨텍스트와 일관된 출력을 얻을 수 있지만 비용과 메모리 사용량이 증가.​
  * 더 짧은 값: 응답 속도가 빨라지고 비용이 절감되지만 출력이 불완전하거나 불일치할 수 있다.​
* **Stop Sequences (중단 시퀀스):** 특정 문자열이 출력에 나타나면 모델이 텍스트 생성을 중단하도록 지정. 여러 개의 중단 시퀀스를 설정할 수 있으며(최대 4개), 어느 하나라도 나타나면 생성이 멈춘다.​
  * 비용 관리: 토큰 사용을 제한하여 비용을 절감한다.​
  * 구조화된 출력: XML이나 JSON 형식에서 불필요한 정보 추가를 방지한다.​
  * 예시: Stop sequence를 `"</output>"`로 설정하면 이 태그가 나타나는 순간 생성이 중단된다.​

```
pythonresponse = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "List three fruits."}],
    stop=["\n"]  # 줄바꿈에서 중단
)
```

### 3-3. 반복 제어 매개변수

* **Frequency Penalty (빈도 페널티):** 이미 생성된 토큰이 반복될 때마다 해당 토큰의 확률을 감소시킨다. 토큰이 많이 반복될수록 페널티가 커진다.​
  * 범위: -2.0 \~ 2.0​
  * **양수 값**: 반복되는 토큰을 억제하여 다양성을 높입니다. 학술 에세이, 창작 글쓰기에 적합.​
  * **음수 값**: 반복을 장려.​
* **Presence Penalty (존재 페널티):** 이미 한 번이라도 출력에 나타난 토큰을 억제. Frequency Penalty와 달리 토큰이 몇 번 나타났는지와 관계없이 동일한 페널티를 적용​
  * 범위: -2.0 \~ 2.0​
  * **양수 값**: 새로운 토큰 사용을 장려하여 더 다양한 콘텐츠를 생성.​
  * **음수 값**: 이미 사용된 토큰을 재사용하도록 장려.​

Frequency Penalty는 "like", "and", "as a result" 같은 단어가 자주 반복되는 것을 방지하고, Presence Penalty는 이미 언급된 주제나 개념을 다시 언급하지 않도록 유도한다.​

일반적으로 Temperature/Top-P와 마찬가지로 Frequency Penalty와 Presence Penalty 중 하나만 조정할 것을 권장 한다.

### 3-4. 추론 모델 전용 매개변수

OpenAI의 o-시리즈(o1, o3-mini, o3 등)와 같은 추론 모델은 복잡한 문제를 단계별로 분해하여 해결하는 특별한 능력을 갖추고 있으며, 이를 위한 전용 매개변수가 있다.​

* **Reasoning Effort (추론 노력):** 추론 모델이 응답을 생성하기 전에 얼마나 많은 추론 토큰(reasoning tokens)을 사용할지 제어.​
  * **low**: 속도와 비용 효율성을 우선.​
  * **medium**: 속도와 추론 정확성의 균형을 맞춤(기본값).​
  * **high**: 더 완전하고 심도 있는 추론을 수행.​

```
pythonresponse = client.chat.completions.create(
    model="gpt-5",
    reasoning={"effort": "medium"},
    messages=[{"role": "user", "content": "이 행렬의 전치를 계산하는 bash 스크립트를 작성해주세요"}]
)
```

* **Reasoning Tokens (추론 토큰 수):** Anthropic Claude 3.7+ 및 Gemini 2.5+에서 사용되는 매개변수로, 추론에 사용할 최대 토큰 수를 직접 지정.​

추론 모델은 **추론 토큰**을 사용하여 "생각"하며, 프롬프트를 분해하고 여러 접근 방식을 고려한 후 응답을 생성한다.

추론 토큰은 API를 통해 직접 보이지 않지만 컨텍스트 윈도우를 차지하며 출력 토큰으로 과금된다.​

### 3-6. 매개변수 조정 프로세스

효과적인 매개변수 조정을 위한 단계별 접근법:​

* **1단계: 사용 사례 파악** - 콘텐츠 유형(기술적/창의적)을 명확히 한다.
* **2단계: 초기값 설정** - 사용 사례에 맞는 초기 매개변수 값을 설정한다. 기술 문서라면 temperature를 낮게 시작합니다.
* **3단계: 출력 생성 및 검토** - 샘플 출력을 생성하고 품질을 평가한다.
* **4단계: 한 번에 하나씩 조정** - 각 매개변수의 영향을 명확히 파악하기 위해 한 번에 하나씩만 변경한다.​
* **5단계: 반복** - 원하는 결과를 얻을 때까지 2-4단계를 반복한다.

매개변수 조정은 모델의 크기에 따라 다르게 작동할 수 있다. 더 큰 모델은 높은 무작위성을 더 효과적으로 처리하는 반면, 작은 모델은 높은 설정에서 출력 품질이 저하될 수 있다
