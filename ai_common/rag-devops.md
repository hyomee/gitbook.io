# RAG 인프라 DevOps  가이드

RAG 시스템을 프로덕션 환경으로 이전하려면 MLOps/DevOps 파이프라인, 컨테이너 오케스트레이션, 모니터링 인프라가 통합적으로 구성되어야 한다. 이는 전통적인 소프트웨어 개발 DevOps와 머신러닝 특화 MLOps의 결합이 필요한 영역이다.

핵심 인프라 구성 요소

## 1. 컨테이너화 및 오케스트레이션

### Docker 컨테이너화

RAG 시스템의 각 마이크로서비스(리트리버, 생성기, 임베딩 서버 등)를 독립적인 컨테이너로 패키징한다. 이를 통해 다음을 달성한다:

* 환경 일관성: 개발, 스테이징, 프로덕션 간 동일한 실행 환경 보장
* 격리: 서로 다른 라이브러리 버전 요구사항을 가진 컴포넌트 간 충돌 방지
* 재현성: CUDA 버전, Python 패키지 의존성을 이미지에 고정

### Kubernetes 오케스트레이션

프로덕션 RAG 시스템은 일반적으로 Kubernetes(K8s) 클러스터에 배포된다:

* 자동 스케일링: HorizontalPodAutoscaler를 사용해 트래픽에 따라 Pod 수 조정
* 자가 복구: 장애 발생 시 컨테이너 자동 재시작
* 서비스 디스커버리: 내부 DNS를 통한 마이크로서비스 간 통신
* 리소스 관리: CPU/GPU 할당 정책, 메모리 제한 설정
