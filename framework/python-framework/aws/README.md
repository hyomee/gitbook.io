# AWS

Agent Squad와 Strands Agents의 차이점AWS에서 제공하는 두 오픈소스 에이전트 프레임워크인 Agent Squad와 Strands Agents는 모두 멀티 에이전트 시스템을 구축할 수 있지만, 초점과 설계 철학에서 큰 차이를 보입니다.&#x20;

| 특징                | Agent Squad                                                            | Strands Agents                                                                         |
| ----------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **핵심 역할**         | 여러 전문 에이전트 간의 \*\*라우터(Router)\*\*이자 **오케스트레이터(Orchestrator)**          | 단일 에이전트의 내부에서 **모델 기반 도구 사용**에 집중하는 **툴킷(Toolkit)**                                    |
| **멀티 에이전트 접근 방식** | **컨텍스트 분리가 엄격한 다수의 전문 에이전트들**을 관리하고, 사용자 질의를 가장 적합한 에이전트로 라우팅하는 방식에 특화 | 모델의 추론 능력을 활용해 여러 에이전트 간의 조정을 관리하거나, **단일 에이전트가 복잡한 작업을 수행하도록 설계**하는 방식                |
| **개발 철학**         | 미리 정의된 워크플로에 따라 여러 에이전트의 협업을 조정하는 **구조적인 접근** 방식                       | 복잡한 작업 흐름을 코드로 하드코딩하는 대신, **모델의 추론에 의존**해 작업 계획을 세우고 도구를 호출하는 방식                       |
| **적합한 사용 사례**     | 고객 지원, 의료 상담, 여행 계획 등 **여러 특화된 에이전트가 필요한 복잡한 도메인**                     | **단일 에이전트가 복잡한 작업을 해결**하거나, 모델 기반의 유연한 도구 사용이 중요한 경우                                   |
| **통합**            | Bedrock Agents, Amazon Lex, Lambda 등 AWS 서비스와의 통합에 최적화                 | Bedrock 외에도 OpenAI, [Anthropic](https://www.anthropic.com/) 등 **다양한 LLM API와의 통합을 지원** |
| **개발 난이도**        | 여러 에이전트의 역할과 라우팅 로직을 설정하는 데 초점                                         | 최소한의 코드만으로도 에이전트를 구축할 수 있어 개발이 간편                                                      |
| **결론**            | \*\*'교통경찰'\*\*처럼 여러 전문가들을 관리하며 사용자의 의도를 파악해 올바른 전문가에게 연결해주는 역할에 적합     | \*\*'DIY 툴킷'\*\*처럼 하나의 LLM이 스스로 도구를 사용해 문제를 해결하도록 만드는 역할에 적합                           |

**상호 보완적인 관계**\
Agent Squad와 Strands Agents는 상호 배타적인 관계가 아니라, 함께 사용할 수 있습니다. 예를 들어, Strands Agents로 만든 마이크로 에이전트를 Agent Squad의 구성원으로 포함시켜, Agent Squad의 광역 라우팅 기능과 Strands의 정교한 도구 사용 능력을 결합할 수 있습니다
