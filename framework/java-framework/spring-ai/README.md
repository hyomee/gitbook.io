# Spring AI

## 1. Spring AI 프로젝트를 개발할 때 고려해야 할 주요 사항

Spring AI 프로젝트를 개발할 때 고려해야 할 주요 사항은 기술 스택 일관성, 보안 요구사항, AI 통합 목적, 성능 및 확장성, 그리고 유지보수와 확장 전략으로 기존 Spring 기반 환경에서 가장 자연스럽고 안전하게 AI 통합을 실현할 수 있지만, 프로젝트 목적(내재화 vs. AI 중심 서비스)과 기술 요구(생태계, 파인튜닝, 실시간 추론 등)에 따라 설계 방향을 명확히 해야 합니다

#### 1.1 기술 스택 및 통합 방식

* Java/Spring 생태계를 그대로 활용할 수 있어 기존 구조(Service, Controller, Config 등) 내에서 LLM, 프롬프트 관리, 응답 처리까지 단일 환경에서 일관성 있게 통합됩니다.​
* Python 생태계 기반 모델 파인튜닝, 로컬 LLM 운영, 맞춤형 RAG 파이프라인 등은 Spring AI가 아닌 Python 환경이 더 적합할 수 있습니다.​

#### 1.2 보안 및 정책

* 금융, 공공기관, 대기업 등 민감 데이터 및 내부 정책 요구가 큰 경우, 데이터 이동 없이 Spring 애플리케이션 내에서 직접 관리할 수 있어 보안성 및 규정 준수 측면에서 유리합니다.​
* 인증, 로깅, 감사(audit) 등 기존 엔터프라이즈 규정을 그대로 적용할 수 있습니다.​

#### 1.3 성능·인프라·확장성

* Spring AI는 빠른 통합과 확장성 면에서 강점이 있지만, 고성능 대형 모델 추론이나 자체 모델 학습이 필요한 경우에는 외부 Python 서버와 연동하거나 ONNX, DL4J 등 Java 친화 도구를 별도로 고려해야 합니다.​
* 다양한 API(OpenAI, Azure AI 등)와의 손쉬운 연동성 및 모듈화는 장점입니다.​

#### 1.4 관리·운용·유지보수

* 일관된 Java/Spring 코드 패턴, 의존성 및 설정 자동 관리, 반복작업 자동화(예외처리, API Key 관리, 응답 파싱 등)로 복잡성이 줄고 유지보수가 쉬워집니다.​
* 표준화된 구조(DI, REST, 모듈화)로 팀 내 협업과 품질 관리에 이점이 있습니다.​

#### 1.5 실무 적용시 추가 주의점

* 토큰 제한 등 LLM 인퍼런스 제약, 프롬프트 최적화, 메타데이터 활용(사용량, 레이트 리밋) 등 AI 특화 이슈에 대한 이해와 설계가 필요합니다.​
* 작은 단위부터 직접 프로젝트에 적용하며 점진적으로 확장해가는 접근이 바람직합니다.​

## 2. Spring Boot  + AI

Spring AI 기반 프로젝트는 일반적인 Spring Boot + AI 의 두 축으로 보아야 하므로 다음과 같은 점을 염두에 두고 설계를 해야 합니디.

### 2.1. 아키텍처 & 책임 분리

#### 2.1.1. AI 호출 레이어 분리

* `ChatClient` / `ChatModel` 같은 Spring AI 추상화를 감싸는 **Service 레이어**를 분리
* 컨트롤러에서 직접 프롬프트 만들고 모델 호출하지 말고, `AiService` 같은 빈을 통해 호출하도록 구조화.

#### **2.1.2. 도메인 로직 vs AI 로직 분리**

* 비즈니스 규칙(요금 계산, 승인 조건 등)은 **순수 Java/Spring 코드**로,
* 요약/추천/자연어 처리 같은 부분만 AI에 위임.
* 이렇게 해야 나중에 모델을 교체하거나 AI 비율을 조정하기 쉬워

#### **2.1.3. 멀티 프로바이더/모델 전략**

* Spring AI는 OpenAI, Anthropic, Google, AWS, Ollama 등 여러 프로바이더를 지원하므로, 설정으로 모델을 교체할 수 있게 설계.
* 예: `primary-model`, `fast-model`, `cheap-model` 같은 **논리 이름**을 만들어두고, 실제 프로바이더/모델 ID는 `application.yml`에서 매핑

***

### 2.2. 프롬프트 & 출력 설계

#### **2.2.1. 프롬프트 템플릿 관리**

* Spring AI의 `PromptTemplate` / 템플릿 파일(예: `src/main/resources/prompts/...`)로 버전 관리 가능하게 구성.
* 하드코딩된 문자열 대신,

```java
PromptTemplate template = new PromptTemplate("You are a ...");
```

형태 또는 외부 파일 로딩.

#### **2.2.2. 구조화된 출력(JSON → POJO)**

* Spring AI는 JSON 형태로 응답을 받아 Java 객체로 매핑하는 구조화 출력 기능 지원
* 모델에게 “이런 JSON 스키마로 응답하라”고 지시하고,해당 JSON을 DTO/VO에 바인딩 → 후속 로직을 타입 안전하게 처리.

#### **2.2.3 검증 & 후처리**

* AI가 반환한 결과에 대해:
  * JSON 스키마 검증
  * 값 범위 체크
  * 금지어/규칙 위반 여부 필터링
* “AI가 말했으니 사실이다” 가 아니라, validation layer를 한 번 더

***

### 2.3. RAG & 데이터 연동

#### **2.3.1. 벡터 스토어 설계**

* Spring AI는 PGVector, Milvus, Pinecone, Redis 등 다양한 벡터 DB 연동을 지원
* 선택 포인트:
  * 운영 중인 DB와 함께 쓸 수 있는지(Postgres/PGVector 등)
  * 규모 & 비용
  * 관리 난이도(Managed vs Self-hosted)

#### **2.3.2. 문서 파이프라인(ETL)**

* 원천 데이터 → 청소/정규화 → chunking → 임베딩 생성 & 저장.
* 이 파이프라인을 배치(Spring Batch) 또는 이벤트 기반(SQS/Kafka + Spring) 으로 자동화.

#### **2.3.3. 쿼리 전략**

* RAG 시, 단순 top-k 검색 말고:
  * 쿼리 리라이팅(사용자 질문 → 검색 친화 쿼리로 변환)
  * 필터(tenant, 권한, 날짜 등) 적용
* 검색 결과를 프롬프트에 넣을 때는 “출처/메타데이터”도 함께 넣어, 이후 근거 출처를 UI에 보여줄 수 있게 설계.

***

### 2.4. 비용, 성능, 스케일링

#### **2.4.1. 캐싱**

* 동일/유사 요청이 많다면:
  * Spring Cache (예: Redis) + 프롬프트 해시 기반 캐시 키.
* Spring AI 자체도 캐시/리트라이 등의 기능을 제공하므로 적절히 활용.

#### **2.4.2. 타임아웃 & 재시도**

* 외부 LLM API는 네트워크/서버 상태에 따라 느릴 수 있으므로:
  * `WebClient` 타임아웃
  * Spring Retry로 재시도 정책
  * 서킷 브레이커(Resilience4j) 적용

#### **2.4.3 비용 모니터링**

* 요청당 토큰 사용량, 월별 사용량을 로깅/메트릭으로 수집.
* 사용자별/기능별 쿼터를 두고 초과 시 fallback 경로(요약 품질 낮추기, 모델 다운그레이드 등)를 설계.

#### **2.4.4. 비동기/스트리밍**

* Spring AI는 스트리밍 응답도 지원하므로, 긴 답변은 SSE/WebSocket으로 바로바로 흘려주는 것도 고려.

***

### 2.5. 보안 & 프라이버시

#### **2.5.1. 민감정보 마스킹**

* LLM에 보내기 전에:
  * 이름/전화번호/주민번호 등 PII 마스킹 또는 토큰화.
* 응답을 다시 사용자에게 보여줄 때 역매핑이 필요한 경우, 내부 DB에 매핑 테이블 관리.

#### **2.5.2. API Key & 시크릿 관리**

* LLM 프로바이더 키는 `application.yml`이 아닌 환경변수 / Vault / Config Server 사용.
* 권한이 없는 서비스/개발자가 키를 직접 보지 못하게 IAM 정책 설정.

#### **2.5.3. 데이터 거버넌스**

* 어떤 데이터가 외부로 나가는지(프롬프트 내용) 로깅 & 감사(audit) 가능하게.
* 규제 산업(금융/헬스케어 등)은 “training에 사용되지 않는 엔터프라이즈 플랜” 여부도 확인.

***

### 2.6. 관측(Observability) & 품질 관리

#### **2.6.1. 로그/트레이싱**

* AI 호출 전/후 로그:
  * 요청 ID, 사용자 ID(또는 익명화된 키)
  * 사용 모델, 토큰 수, Latency
* OpenTelemetry + Spring Boot Actuator로 전체 트레이스에 LLM 호출 구간 포함.

#### **2.6.2. 프롬프트/응답 샘플링 저장**

* 개인 정보가 없는 수준에서 **샘플링된 프롬프트 & 응답**을 저장해:
  * 품질 리뷰
  * 프롬프트 튜닝
  * 버그 재현에 활용.

#### **2.6.3. A/B 테스트 & 평가**

* Spring AI는 모델/프롬프트 평가 도구도 제공하려는 방향으로 발전 중.
* 서로 다른 프롬프트/모델을 트래픽의 일부에만 적용해 인간 평가(thumbs up/down) + 자동 메트릭으로 비교.

***

### 7. 일반적인 Spring Boot 프로덕션 베스트 프랙티스도 그대로

AI 프로젝트라고 해도 결국 **Spring Boot 애플리케이션**이기 때문에, 기본적인 것들을 같이 챙겨야 합니다.

* 계층형 아키텍처, 패키지 구조 정리
* 프로파일별 설정(dev/stage/prod)
* 헬스 체크(`/actuator/health`), readiness/liveness probe
* 적절한 테스트:
  * 단위 테스트(도메인 로직)
  * 통합 테스트(WebMvcTest, DataJpaTest 등)
  * AI 호출은 **Mocking**해서 테스트(실제 LLM 호출 X)
* CI/CD 파이프라인, 롤백 전략

## &#x20;3. Python & Spring AI

#### 3.1. 생태계 및 기술 호환성

* **Spring AI**는 Java/Spring 기반 엔터프라이즈 환경에 최적화되어 있어, 기존 비즈니스 로직과 일관된 구조(DI, REST API, 보안 프레임워크 등) 내부에서 LLM 관리, 프롬프트 처리, 응답 파싱 등이 가능합니다.​
* **Python 기반 AI 서버**는 수많은 최신 AI/ML 라이브러리(PyTorch, TensorFlow, HuggingFace 등) 활용이 가능하고, 빠른 프로토타타이핑, 모델 파인튜닝, 멀티모달 실험, 데이터 분석에 특화되어 있습니다.​

#### 3.2 성능 및 최신 모델 지원

* Spring AI의 경우 JVM 오버헤드로 인해 대규모 추론이나 로컬 모델 실행에서 성능 면에서 Python에 비해 한계가 있을 수 있습니다.​
* Python 서버는 GPU 직접 활용, 벡터 임베딩/파인튜닝, RAG 파이프라인 커스터마이징 등 최신 연구·모델을 즉시 적용하는 데 강점이 있습니다.​

#### 3.3. 엔터프라이즈 관리 및 보안

* Spring AI는 기존의 인증, 로깅, 감사, 정책 적용 등을 Spring 패턴으로 자연스럽게 통합 관리할 수 있어 금융/공공 등 엔터프라이즈 환경에서 유리합니다.​
* Python 서버는 관리, 보안, 확장성 구현이 상대적으로 자유롭지만 추가적인 설계가 필요합니다.​

#### 3.4. 운영 방식 및 확장성

* Spring AI는 Spring Boot 앱에 바로 통합되어 별도 Python 서버 없이 프롬프트, LLM 호출, 응답 처리가 가능하므로 운영 및 유지보수가 단순합니다.​
* Python 서버는 Flask, FastAPI 등 다양한 경량/비동기 프레임워크를 통해 독립적이고 유연하게 구축할 수 있어 AI 중심 서비스나 연구 환경에 적합합니다.​

#### 3.5. 선택 가이드

* **Spring AI**: 기존 시스템이 Java/Spring 기반이거나 보안·관리·정책 준수가 중요한 엔터프라이즈 환경에 적합합니다.​
* **Python 기반 서버**: 최신 AI 실험, 커스텀 모델, 빠른 프로토타입 개발 및 다양한 AI 연구에 적합합니다.​

## 4. Spring AI 구축 유형

Spring AI로 구축 가능한 애플리케이션 유형은 기존 Spring 생태계(REST API, 웹앱, 엔터프라이즈 백엔드)에 생성형 AI, 챗봇, 텍스트·이미지·음성 생성 기능을 자연스럽게 통합하는 것이 핵심입니다.​

### 4.1. 주요 적용 예시 및 유형

* **챗봇/컨버세이셔널 API**: GPT 또는 다양한 LLM 연동으로 사용자 질의에 맞는 답변 생성, 대화 서비스, 고객 지원 챗봇 등 실시간 응답형 애플리케이션.​
* **문서 생성·요약 서비스**: 이메일, 게시글, 보고서, 안내문 등 자동 텍스트 생성 및 요약 기능 API, RAG 기반 검색·요약 기능도 손쉽게 구현 가능.​
* **이미지·음성 생성**: DALL-E, Whisper 등과 연동해 이미지 생성, 음성·텍스트 변환 기능을 REST API 또는 시각화 서비스로 제공.​
* **AI 기반 업무 자동화**: 코드 리뷰, 정책 이슈 처리, 데이터 파싱 등 내부 프로세스를 자동화하거나, 워크플로우 오케스트레이션(에이전트 시스템).​
* **AI 어시스턴트**: 일정 관리, 추천 시스템, 작업 자동화 등 엔터프라이즈 업무보조 기능에 AI를 추가해 생산성 향상.​
* **로컬 및 외부 모델 통합 서비스**: Ollama, OpenAI, Azure, Vertex AI 등 다양한 모델 제공 업체와 통합하여 서비스 구조 내 AI 기능을 추가.​

### 4.2. 구축 방식

* 기존 컨트롤러 또는 서비스에 프롬프트, LLM 모델 호출, 결과 후처리 로직을 삽입.​
* REST API, 웹소켓, 비동기 메시징 등 기존 Spring 패턴을 그대로 지원하면서 AI 기능을 추가.​
* 엔터프라이즈 데이터(DB, Queue, File 등)와 AI 모델 연계가 쉽다.​
